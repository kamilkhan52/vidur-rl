## Findings

### [minor] The docstring's gate command fails as pasted
`headroom.py:252-253`. Failure scenario: the operator copies the two indented lines after `# when all 4 chains are done:`. Bash joins `...b41_tool_w4000,\` with the next line's two leading spaces, so `--out` gets `evolve/rl_plan/out/b41_tool_w4000,` and the other 3 dirs become a stray positional argument. Evidence: the same two lines fed to `printf '<%s>\n'` give `<evolve/rl_plan/out/b41_tool_w4000,>` and `<evolve/rl_plan/out/b41_tool_w6000,evolve/...conv_w6000>` as separate words. argparse then exits with "unrecognized arguments". This fails loudly and cannot give a wrong verdict. Fix: put the comma list on one line, or write it as `--out "$(echo evolve/rl_plan/out/b41_{tool,conv}_w{4000,6000} | tr ' ' ,)"`. Hashed file: no.

### [minor] B runs print and store a "missing" window verdict
`headroom.py:2212`. Every B mode ends with `rows["verdict"] = window_verdict(rows, shas, ..., None)`. That function looks only for true-future closed rows at the pilot's `closed` sha, so in a `b41_*` directory it always prints and stores `{"label": "missing", "reason": "0 closed full-horizon lookahead rows"}`, even after a complete B run. The gate ignores stored labels, so it is unaffected. An operator checking a chain's log could still read this as a failed closed run. Fix: when `step_b`, store `b_inputs`' completeness (or a `window_verdict` computed on `b_inputs`' view) instead, or skip the stored verdict. Hashed file: no. `window_verdict` is in `post_sha`, so change only the call in `main`.

### [nit] `weight_from` provenance omits which weights were averaged
`headroom.py:2129`. The params record `windows`, `weights` and `weight_labels`, so the `tails` sentinel (1.6e10) shows up with nothing saying it was excluded. `weight` is recorded, and the labels make the exclusion derivable, so nothing is lost. Adding `weight_fallback` and `weight_rule` (already computed in `src`) would make the row self-explanatory. Doing so would re-key B rows, so do it before launch or not at all. Hashed file: no.
